# フロー手順書の表記規約（エージェント共通）

このディレクトリの `*.md` は各操作（/aidd-spec /aidd-tasks /aidd-implement など。コマンド名はエージェント組み込みコマンドとの衝突を避けるため `aidd-` プレフィックス付き。手順書ファイル名にはプレフィックスを付けない）の**手順書本体**である。
エージェント固有の定義（Claude Code の `.claude/commands/` 等）は薄いラッパーであり、ここを参照する。手順書は特定のエージェントに依存しない。

## 表記の読み替え

| 手順書内の表記 | 意味 |
|---|---|
| （コマンド引数） | ラッパーから渡される入力（要件文・ループ名・指摘内容など）。無ければ手順書の省略時ルールに従う |
| 知識ファイル / `ccsdd` などの名前 / 「X スキル」 | `.aidd-docs/knowledge/<名前>.md` のこと。指示されたら作業前にファイル読み込み機能で読むこと（Claude Code では `.claude/skills/` の同名スキル経由でも可） |
| AskUserQuestion | 人間に選択肢を提示して選ばせる操作。Claude Code では AskUserQuestion ツール、他エージェントでは選択肢を列挙して返答を待つ |
| Read / Grep などのツール名 | Claude Code のツール名。他エージェントは同等機能で代替する |
| サブエージェント / 作業者 | 作業を委任する補助エージェント。Claude Code では Agent ツール（読み取り専用の調査は Explore、実装は general-purpose を worktree 分離で）。対応機能がないエージェントは逐次実行にフォールバックする |
| 停止する / 作業を止める | そのターンの作業を終え、人間の入力を待つこと。勝手に次の段階へ進まない |

## ルールファイルの読み込み

`.aidd-docs/rules/` は常時読み込みではなく、各手順書の「事前準備」が指定するタイミングで読む（常駐コンテキストを小さく保つため）:

| 指定 | 読むタイミング |
|---|---|
| **必須** | その手順書の作業を始める前に読む |
| **条件付き** | 手順書に書かれた判断に迷ったときだけ読む |
| 記載なし | 読まない（その手順書だけで完結する） |

**同一セッション内で既に読んだルールファイルを再読しない。** フェーズごとに新しいコンテキストで始める運用（下記「次の一手」行）のため、通常は1セッションにつき各ファイル1回で足りる。

## 停止点の「次の一手」行

手順書が人間の入力を待って停止するときは、提示する内容の**最終行**として次の書式で案内する。書式の定義はこのファイルにのみ置き、各手順書は「`flows/README.md` の書式で次の一手を示す」と参照する。

**軽い境界**（承認すれば次のフェーズへ自動継続する停止点）— 1行:

```
次: `/aidd-approve 001-user-auth`（承認するとタスク分解まで自動で進みます）
```

**重い境界**（tasks 承認後と実装完了後。自動継続せず、次のフェーズを新しいコンテキストで始める）— 2行:

```
次: `/clear` してから `/aidd-implement 001-user-auth`
（実装フェーズは新しいコンテキストで始めるとトークン消費を抑えられます。進行状況は tasks.md に残るので clear しても失われません）
```

- ループ名は必ず具体名を埋める（`<ループ名>` のようなプレースホルダのまま出さない）
- 括弧の補足行は重い境界でのみ付ける
- この行はレビュー依頼の各項目（要点サマリ・判断ポイント等）を置き換えるものではなく、末尾に追加する
- 停止する前に、チャット上で確定した決定事項を成果物ファイルへ書き戻しておくこと（`/clear` や自動コンパクションで失われないようにするため。書き戻し先は各手順書に記載）

## 手順書を変更するとき

`template-maintenance` 知識ファイルの一貫性マトリクスに従う（ラッパー・README・AGENTS.md との同期が必要）。
